# Engineering process: gates, documents and owners

Every part moves through six gates. A gate passes when `engsys check <record> --gate Gn` reports no errors
and an independent reviewer (the `design-reviewer` agent, or a person) signs the review entry in the record.

```
 data inputs ──► G0 intake ──► G1 concept CAD ──► G2 design release ──► G3 process release ──► G4 FAI / PPAP ──► G5 production + change
                     │               │                  │                      │                     │                  │
               requirements     model + params    design review          routing + flow         AS9102 forms      NCR / 8D
               export screen    source tags       drawing check          PFMEA                  PPAP elements     ECN, rev bump
               characteristics  CAD verify        stack-ups, DFM         control plan           sign-off          lessons -> FMEA
                                                  DFMEA, BOM             inspection plan
```

## The digital thread

One file, `part-record.json` (schema: [`src/engsys/schema/part-record.schema.json`](../src/engsys/schema/part-record.schema.json)),
carries the part through every gate. Documents are generated from it. Characteristic ids (`C1`, `C2`, ...)
are the thread: the same id is the drawing balloon number, the DFMEA and PFMEA link, the control plan row,
the inspection plan row and the FAI Form 3 line.

```
requirement R1 ─► characteristic C7 (KC) ─► DFMEA D3 (S=9) ─► op 40 makes C7 ─► PFMEA P5 ─► control plan row ─► inspection plan row ─► FAI Form 3 result
```

`engsys check` walks this chain for every KC and CC and fails the gate on any break.

## Gates

| Gate | Inputs | Work | Outputs (generated) | Exit criteria checked by `engsys check` |
|---|---|---|---|---|
| **G0 Intake** | TDP or sample, FLIS, IPB, RFQ, mating-part data | Export-control screen, requirements capture, start the characteristics list from the drawing or FLIS | Part record, characteristics list | Part id, rev, units, export-control fields set. At least one requirement. Every characteristic has a source tag |
| **G1 Concept CAD** | Part record | Parametric model (build123d), CAD verification in FreeCAD | `.py`, `.step`, renders, `_params.json`, design-intent log | G0 plus: every characteristic carries a nominal and limits (or a GD&T tolerance) |
| **G2 Design release** | Model, drawing, record | Design review, drawing check (Y14.5), tolerance stack-ups, DFM review, strength check, DFMEA, BOM | Design review record, stack-up report, DFMEA, BOM, drawing | G1 plus: no open blocker or major findings; every requirement linked; every KC/CC in the DFMEA; no KC/CC still `ASSUMED`; every High AP has an action; every stack-up meets its target worst case (or RSS when the stack-up allows it); DFMEA S >= 9 lines touch only KC/CC characteristics |
| **G3 Process release** | Released design | Routing, process flow, PFMEA, control plan, inspection plan, work instructions, gauge list | Routing, PFMEA, control plan, inspection plan | G2 plus: every characteristic is made at an operation; every KC/CC is in the PFMEA, the control plan (with gauge, sample, frequency, reaction plan) and the inspection plan; PFMEA S is not below the S of the DFMEA line it links (`dfmea_ids`); every High AP has an action |
| **G4 FAI / PPAP** | First production parts | Ballooned drawing, measure every characteristic, material certs and special-process certs | AS9102 Forms 1-3, PPAP / AS9145 checklist | G3 plus: every characteristic on the drawing has an FAI result; no result out of tolerance without an NCR number |
| **G5 Production and change** | NCRs, customer changes, shop feedback | 8D, ECN with impact analysis, partial or full FAI per AS9102 when the change triggers one | ECN log, updated documents at the new rev | Every ECN lists affected documents and characteristics; the record rev matches the latest approved ECN |

## Document map

| Document | Standard | Generated by | Sheet / file |
|---|---|---|---|
| Characteristics / balloon list | AS9102 Form 3 numbering, AS9103 | `engsys build` | `Characteristics` |
| Design review record | AS9100D 8.3.4 | `design-reviewer` agent writes findings into the record | `Design-Review` |
| Tolerance stack-up report | ASME Y14.5 (MMB/LMB), worst case + RSS + Monte Carlo | `engsys stackup` | `Stack-ups` |
| DFMEA | AIAG-VDA 2019 | `fmea-chain` skill fills the record; `engsys build` writes it | `DFMEA` |
| BOM | MIL-STD-31000B | record `bom` | `BOM` |
| Routing / process flow | AS9145 | record `process` | `Routing` |
| PFMEA | AIAG-VDA 2019 | `fmea-chain` skill | `PFMEA` |
| Control plan | AIAG Control Plan 2024, AS9145 | `fmea-chain` skill | `Control-Plan` |
| Inspection plan | AS9102, AS9103 | `fai-as9102` skill | `Inspection-Plan` |
| FAI Forms 1-3 | AS9102 Rev C | `engsys build` from FAI results | `FAI-Form1/2/3` |
| ECN log | EIA-649C | `ecn` skill | `ECN-Log` |
| Gate report | this document | `engsys check` | `_Gate-Report (Rev - X).md` |

Still outside the tool (done by agents or people, recorded in the part record): drawings
(the drawing generator in the 4277 pipeline), work instructions, gauge R&R / MSA, process capability
studies, the PPAP warrant.

## Who does what

| Role | Agent / skill | Writes to the record |
|---|---|---|
| Lead engineer | `eng-system/CLAUDE.md` | gate decisions, requirement list, export screen |
| CAD builder | existing CAD agent on `D:\CAD-Agent` | characteristic nominals, `_params.json` |
| Design reviewer | `claude/agents/design-reviewer.md` + `design-review` skill | `design_reviews` |
| Tolerance analyst | `claude/agents/tolerance-analyst.md` | `stackups` |
| DFM reviewer | `claude/agents/dfm-reviewer.md` | findings in `design_reviews`, `process` suggestions |
| FMEA author | `claude/skills/fmea-chain` | `dfmea`, `process`, `pfmea`, `control_plan` |
| Inspection planner | `claude/skills/fai-as9102` | `inspection_plan`, `fai` |
| Change control | `claude/skills/ecn` | `changes`, rev bump |

The reviewer never edits CAD and the CAD builder never signs a review.
